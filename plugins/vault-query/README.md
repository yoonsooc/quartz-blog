# vault-query

옵시디언의 동적 조회(Bases, Dataview)를 Quartz 빌드 시점에 실행해서, 그 결과를 정적인 표와 문단으로 바꿔 주는 로컬 플러그인입니다.

## 왜 필요한가

옵시디언의 `.base` 뷰와 `dataviewjs` 블록은 저장된 내용이 아닙니다. 옵시디언 앱이 실행 중에 볼트를 조회해서 그때그때 그려 주는 화면입니다. Quartz는 마크다운 파일을 HTML로 바꾸는 정적 사이트 생성기라서 이런 조회를 실행하지 못합니다. 그래서 아무 처리를 하지 않으면 게시된 페이지에는 코드 블록이나 깨진 임베드만 남습니다.

또 하나의 문제는 조회 대상의 위치입니다. 이 블로그는 볼트의 특정 배포 대상 폴더만 `content`로 연결해 게시합니다. 그런데 조회 대상 노트는 해당 폴더 밖에 있으므로 Quartz는 그 데이터를 볼 수 없습니다.

이 플러그인은 두 문제를 함께 해결합니다. 빌드할 때 **볼트 루트에서 직접** 노트의 frontmatter를 읽어 조회를 실행하고, 결과만 페이지에 넣습니다. 조회 대상 노트 자체는 게시되지 않습니다.

## 지원하는 구문

| 옵시디언 구문                     | 게시 결과                                       |
| --------------------------------- | ----------------------------------------------- |
| `![[이름.base#뷰 이름]]`          | 해당 뷰를 평가한 마크다운 표                    |
| `![[이름.base]]`                  | 첫 번째 뷰를 평가한 마크다운 표                 |
| ` ```base ` 코드 블록             | 블록 안의 Base 정의를 평가한 표                 |
| ` ```dataviewjs ` 코드 블록       | `dv.paragraph`, `dv.table` 등이 출력한 마크다운 |
| `` `= this.price * this.count` `` | 계산된 값 (Dataview 인라인 식)                  |
| `key:: value` 줄                  | 페이지에서 숨김 (Dataview 인라인 필드 정의)     |

다른 코드 블록(예: ` ```md `) 안에 적은 임베드 예시는 치환하지 않고 그대로 둡니다.

## 설정

`quartz.config.yaml`에 다음과 같이 등록합니다.

```yaml
- source: "./plugins/vault-query"
  enabled: true
  options:
    sections: *sections
    publicPages: warn
  order: 3
```

`order`는 반드시 `obsidian-flavored-markdown`(30)보다 작아야 합니다. 그 플러그인이 `![[...]]` 임베드를 먼저 처리해 버리면 이 플러그인이 치환할 대상이 사라지기 때문입니다.

| 옵션          | 기본값        | 설명                                                                                                                                                              |
| ------------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vaultRoot`   | 자동 탐색     | 볼트 루트 경로입니다. 생략하면 `content`의 실제 경로에서 위로 올라가며 `.obsidian` 폴더를 찾습니다. 환경변수 `OBSIDIAN_VAULT_ROOT`로도 지정할 수 있습니다.        |
| `sections`    | `[]`          | `section-privacy`와 같은 섹션 정의입니다. `private: true`인 섹션을 비공개 섹션으로 판단하는 데 씁니다.                                                            |
| `publicPages` | `"warn"`      | 비공개 섹션이 아닌 페이지에 볼트 조회 결과가 들어갈 때의 동작입니다. `"warn"`은 경고만 출력하고, `"error"`는 빌드를 중단하며, `"allow"`는 아무것도 하지 않습니다. |
| `emptyText`   | `"결과 없음"` | 조회 결과가 0건일 때 표 대신 표시할 문구입니다.                                                                                                                   |

## 개인정보 관점에서 알아 둘 점

이 플러그인은 게시하지 않는 노트의 값을 게시 페이지로 가져옵니다. 그래서 다음 안전장치를 두었습니다.

- **값만 가져옵니다.** 조회 대상 노트의 본문이나 파일은 출력물에 포함되지 않습니다.
- **비게시 노트로 가는 링크는 텍스트로만 출력합니다.** 예를 들어 `link(file, company)`는 회사 이름 텍스트가 됩니다. 링크를 걸면 깨질 뿐 아니라 볼트 내부 경로가 노출되기 때문입니다. 대상이 `content` 안에 있고 `publish: true`인 경우에만 실제 링크가 됩니다.
- **공개 페이지 점검.** 비공개 섹션 밖의 페이지에 조회 결과가 들어가면 `publicPages` 설정에 따라 경고하거나 빌드를 중단합니다.

비공개 섹션의 페이지는 조회 결과가 본문에 들어간 뒤에 `encrypted-pages`가 본문 전체를 암호화하므로, 표 내용이 평문으로 남지 않습니다.

## 동작 방식

Quartz의 변환 플러그인은 두 단계에서 개입할 수 있습니다. 첫째는 파일을 문자열 그대로 다루는 **텍스트 단계**(`textTransform`)이고, 둘째는 마크다운을 트리 구조(AST)로 파싱한 뒤에 다루는 **마크다운 단계**(`markdownPlugins`)입니다. 이 플러그인은 구문의 성격에 따라 두 단계를 나누어 씁니다.

| 단계          | 처리하는 것                              | 이 단계를 고른 이유                                                                                                                 |
| ------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 텍스트 단계   | `.base` 임베드, `base`/`dataviewjs` 블록 | 결과물이 표와 문단 같은 마크다운 문자열입니다. 문자열로 끼워 넣으면 이후의 파서와 다른 플러그인이 일반 본문과 똑같이 처리해 줍니다. |
| 마크다운 단계 | 인라인 식, 인라인 필드 줄                | 인라인 식은 AST에서 `inlineCode` 노드로 정확히 구분됩니다. 그래서 코드 블록 안의 예시와 섞이지 않습니다.                            |
| 마크다운 단계 | 공개 페이지 점검                         | 페이지 주소(slug)는 이 단계에서야 알 수 있습니다. 텍스트 단계에서 남긴 표식(`<!--vault-query-->`)을 여기서 회수하며 점검합니다.     |

### 파일 구성

```
dist/
├── index.js          플러그인 진입점. 두 단계를 연결하고 실패를 경고 콜아웃으로 바꿉니다.
├── vault.js          볼트 인덱스(경로 수집, frontmatter 지연 로딩과 캐시), 링크 해석, Link 값
├── values.js         빈 값 판정, 비교, 동등성, 날짜 표기 (Bases와 Dataview 공용)
├── markdown.js       표, 셀 이스케이프, 경고 콜아웃 (공용)
├── bases/
│   ├── expr.js       Bases 식(filters, formulas) 파서와 평가기
│   └── render.js     Base 정의 평가: 필터 → 정렬 → 그룹 → 표
└── dataview/
    ├── js.js         dataviewjs 실행기 (dv API, DataArray)
    └── inline.js     인라인 식과 인라인 필드
```

Bases와 Dataview를 하나의 플러그인에 둔 이유는 둘 다 같은 볼트 인덱스와 같은 값 규칙을 쓰기 때문입니다. 플러그인을 나누면 이 공용 코드를 복사하거나 플러그인끼리 서로의 파일을 참조해야 합니다.

### 성능

- 볼트의 파일 경로는 한 번만 훑어서 5초 동안 재사용합니다. 그래서 한 번의 빌드 안에서는 공유되고, `--serve`로 다시 빌드할 때는 새로 훑습니다.
- frontmatter는 실제로 조회되는 파일만 읽고, 수정 시각(mtime)이 같으면 캐시를 씁니다.
- Base 필터의 최상위에 `file.inFolder("...")`가 있으면 그 폴더의 노트만 읽습니다. `dv.pages('"폴더"')`도 마찬가지입니다. 폴더 조건이 없는 조회는 볼트 전체의 frontmatter를 읽으므로 느려질 수 있습니다.

## 지원 범위

지원하지 않는 구문을 만나면 빌드를 멈추지 않습니다. 대신 그 자리에 경고 콜아웃을 남기고 터미널에 `[vault-query]` 경고를 출력합니다. 조용히 틀린 결과를 보여 주는 것보다 눈에 띄게 실패하는 편이 안전하기 때문입니다.

### Bases

- **필터**: 전역 `filters`와 뷰의 `filters`, `and` / `or` / `not` 중첩
- **식**: 문자열·숫자·불리언·목록 리터럴, `==` `!=` `<` `>` `<=` `>=`, `&&` `||` `!`, 사칙연산과 `%`, 날짜에 기간 더하기(`date + "7d"`)
- **속성 참조**: `이름`, `note.이름`, `file.이름`, `formula.이름`
- **`file`**: `name`, `basename`, `path`, `folder`, `ext`, `size`, `ctime`, `mtime`, `tags`, `inFolder()`, `hasProperty()`, `hasTag()`, `asLink()`
- **전역 함수**: `link`, `if`, `now`, `today`, `date`, `number`, `list`, `min`, `max`
- **메서드**: `contains`, `containsAny`, `containsAll`, `isEmpty`, `isTruthy`, `toString`, 문자열(`startsWith`, `endsWith`, `lower`, `upper`, `trim`, `replace`, `split`, `slice`), 목록(`join`, `slice`, `reverse`, `sort`, `unique`), 숫자(`toFixed`, `round`, `abs`, `ceil`, `floor`)
- **뷰**: `order`(열), `properties.*.displayName`(열 이름), `sort`(다중 정렬), `groupBy`, `limit`

지원하지 않는 것은 `file.hasLink()`, 람다를 받는 메서드(`map`, `filter`), `summaries`, 표 이외의 뷰 모양입니다. 카드나 목록 뷰도 표로 그립니다.

### dataviewjs

- **조회**: `dv.pages(source)`, `dv.pagePaths`, `dv.page`, `dv.current`, `dv.array`, `dv.fileLink`
- **source**: `"폴더"`, `"파일 경로"`, `#태그`를 `and` / `or`로 잇고, 항 앞에 `-`를 붙여 제외할 수 있습니다. 괄호 묶음은 지원하지 않습니다.
- **출력**: `dv.paragraph`, `dv.span`, `dv.header`, `dv.el`, `dv.list`, `dv.table`
- **DataArray**: `where`, `filter`, `map`, `flatMap`, `sort`, `groupBy`, `distinct`, `limit`, `slice`, `concat`, `to`, `find`, `some`, `every`, `none`, `first`, `last`, `join`, `sum`, `avg`, `min`, `max`, `length`, 그리고 `rows.period`처럼 속성을 한꺼번에 모으는 문법

지원하지 않는 것은 다음과 같습니다.

- `await`를 쓰는 코드(`dv.io`, `dv.query` 등)는 실행할 수 없습니다. 텍스트 단계가 동기 함수이기 때문입니다.
- `dv.taskList`, `dv.view`, `dv.luxon`은 없습니다.
- 일반 `dataview`(DQL) 블록은 치환하지 않고 그대로 둡니다.
- `dv.current()`는 현재 노트의 필드(frontmatter와 인라인 필드)만 돌려주고 `file.path` 같은 파일 정보는 없습니다. 텍스트 단계에서는 Quartz가 파일 경로를 알려 주지 않기 때문입니다.
- 페이지의 필드는 frontmatter에서만 읽습니다. 조회 대상 노트의 본문에 적힌 인라인 필드와 본문 태그는 읽지 않습니다.

### 인라인 식

`this.필드` 하나를 그대로 출력하는 식과, `this.필드`와 숫자로만 이루어진 사칙연산을 지원합니다. 그 밖의 식(함수 호출, 다른 노트 참조)은 치환하지 않고 원문 그대로 둡니다.

주의할 점이 하나 있습니다. 문단 안에서 `이름:: 값` 모양으로 시작하는 줄은 인라인 필드로 보고 숨깁니다. 그래서 `std::vector는 ...`처럼 `::`가 들어간 단어로 줄을 시작하면 그 줄이 사라질 수 있습니다. 이런 경우에는 `` `std::vector` ``처럼 인라인 코드로 감싸면 됩니다.

## 옵시디언과 다르게 보이는 부분

- **URL 열**은 표가 너무 넓어지지 않도록 도메인만 보이는 링크로 줄입니다.
- **정렬**은 한국어 로캘 기준이라 한글이 영문보다 앞에 옵니다. 옵시디언의 정렬 순서와 다를 수 있습니다.
- **날짜**는 frontmatter에 적힌 문자열 그대로 다룹니다. `dataviewjs`에서 `p.deadline`은 Luxon 날짜 객체가 아니라 `"2026-05-20"` 같은 문자열입니다. ISO 형식 문자열은 문자열 비교만으로도 날짜 순서가 맞습니다.
- **값은 빌드 시점의 스냅샷**입니다. 조회 대상 노트를 고친 뒤에는 다시 빌드하고 배포해야 반영됩니다. `--serve` 미리보기에서도 `content` 밖의 파일 변경은 자동으로 감지되지 않으므로, 게시 노트를 한 번 저장해서 재빌드를 일으켜야 합니다.

## 볼트가 없는 환경 (CI 등)

`content`나 볼트 루트를 찾지 못하면 빌드는 실패하지 않습니다. 경고를 출력하고 블록과 임베드를 원문 그대로 둡니다. 인라인 식은 볼트가 필요 없으므로 이 경우에도 정상적으로 치환됩니다. GitHub Actions에서 빌드하려면 볼트를 함께 체크아웃하고 `OBSIDIAN_VAULT_ROOT`를 지정해야 합니다.

## 개발 메모

다른 로컬 플러그인과 마찬가지로 빌드 과정 없이 `dist/`의 자바스크립트를 직접 수정합니다. 외부 의존성은 루트 `node_modules`의 `yaml`과 `unist-util-visit`만 씁니다. 플러그인을 추가하거나 옮긴 뒤에는 `npm run install-plugins`를 실행해야 `.quartz/plugins`의 링크가 갱신됩니다.

`dataviewjs` 블록은 빌드하는 컴퓨터에서 Node.js 코드로 실행됩니다. 직접 작성한 볼트의 코드만 실행된다는 전제에서 만든 기능이므로, 다른 사람이 쓴 노트를 게시 대상에 넣을 때는 주의해야 합니다.
